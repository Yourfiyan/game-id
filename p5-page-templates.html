Page Templates

Six layout archetypes, their rules, and the shipped screens that use them. Every page in Game ID is one of these six — never a bespoke arrangement.

App shell

Sidebar, top bar, content column and footer. The structural base every other template composes on.

Always
  • One active nav item per view
  • Top bar sync state reflects actual connection status
  • Footer appears only when content exceeds viewport height
Never
  • Show more than five nav items at once
  • Collapse sidebar on wide viewports without user action
  • Overlay the sidebar on top of content on desktop

Library — Grid

Grid of game cards with sidebar and top bar. The primary browse view.

Always
  • Card grid reflows at 1440 minimum width
  • Filters persist across navigation changes
  • Pagination visible when results span multiple pages
Never
  • Mix card and row layouts on the same page
  • Show more than 8 page buttons at once
  • Display a pager when fewer than 50 results exist

Analytics

Chart panels and metric cards with sidebar. The data analysis view.

Always
  • Metric cards align to a single row
  • Chart panels display measured corpus data
  • Distribution bar segments sum to 100%
Never
  • Fabricate figures in a metric card
  • Show a percentage without its raw count
  • Render a trend line on fewer than 3 data points
In use
Analytics — 10:13

Detail

Single game view with game card, row list and action bar. The inspection view.

Always
  • Hero card displays the primary title and confidence
  • Action buttons are primary and secondary only
  • Row list uses the compact row variant
Never
  • Show both hero card and list for the same game
  • Place action buttons between title and metadata
  • Use the grid card variant in a detail view
In use
Game Detail — 10:16

Collections

Named lists of games with sort and filter. The curated view.

Always
  • Collection name is the primary heading
  • Sort state visible on every column header
  • Empty state shown when no games match filter
Never
  • Allow duplicate game entries across collections
  • Hide the filter bar on wide viewports
  • Reorder games by drag without a visible handle
In use
Collections — 10:18

Settings

Account connections and preferences. The configuration view.

Always
  • Account connection status visible at a glance
  • Store disconnection requires explicit confirmation
  • Preference changes apply immediately with undo option
Never
  • Store connection status inferred from game count
  • Allow account deletion without confirmation step
  • Display API tokens or credentials in plain text
In use
Settings — 10:23

List

Row-based game list with metadata columns and sort. The search result view.

Always
  • Rows display title, store, classification, confidence, and enrichment status
  • Sort visible on every clickable column header
  • Row hover highlights the full row, not just the cell
  • Confidence pip present on every row with provenance data
Never
  • Render more than 8 columns on the default viewport
  • Sort on a field absent from >5% of rows (e.g. playtime)
  • Truncate the title column — it must be the widest
  • Use the grid card variant inside a list view
In use
Search — 10:20

Band

Horizontal summary cards in a single scrollable row. The store and account views.

Always
  • Each band card is self-contained with heading, metric, and action
  • Cards share a single horizontal scroll container, not a grid
  • Action buttons appear within the card, not in a separate toolbar
  • Empty band cards still render with placeholder content
Never
  • Stack band cards vertically on any viewport width
  • Mix band and grid layouts on the same page
  • Hide the scroll affordance when the row is not overflowing
  • Use band cards as a substitute for metric cards in Analytics
In use
Stores — 10:21
Accounts — 10:22

Table

Sortable data rows with fixed header, column alignment, and hover states. Used in analytics and detail panels.

Always
  • Header row is visually distinct from data rows
  • Sort indicator appears on the active column only
  • Numeric columns right-align their content
  • Row hover covers the full width, including empty cells
Never
  • Allow horizontal scroll on the default 1440 viewport
  • Sort on columns with no header label
  • Render more than 6 visible columns at once
  • Stripe every other row without a toggle in Settings
In use
Analytics — 10:13 (breakdown table)

Details

Two-column key-value pairs with dividers. The metadata panel in game detail and settings.

Always
  • Label column is right-aligned, value column left-aligned
  • Dividers separate each row, not each pair
  • Long values truncate with ellipsis, not wrap
  • Section header appears above each logical group
Never
  • Use for more than 8 rows without a scroll container
  • Align labels and values to the same edge
  • Nest details inside another details panel
  • Show a divider after the last row
In use
Game Detail — 10:16 (metadata panel)
Settings — 10:23 (account info)

Empty states

Centered illustration, headline, and action for zero-result scenarios. The fallback when no data exists.

Always
  • Headline states what is missing, not that "something went wrong"
  • Primary action is the path out of the empty state
  • Illustration is brand-coloured, never full colour
  • Layout is centered vertically and horizontally in the content area
Never
  • Show a different empty state for every sub-filter
  • Render an empty state inside a card — it must fill the content column
  • Use the error illustration variant for a non-error condition
  • Place the action button below the fold on 1440
In use
Library — 10:9 (no results after filter)
Collections — 10:18 (empty collection)
